Update 0.06 Air-Stuck(s) New Commands: +airstuck +wallstuck The airstuck that is added in this update is not the airstuck that people know in CS:GO. It is the airstuck that was possible in community servers in CS:GO, it is the airstuck that was possible before 64bit update in CS:S. Airstuck gets you stuck in the air as long as you have MoveType MOVETYPE_WALK (meaning you won't be able to airstuck while climbing a ladder). It does this by setting your MoveType to MOVETYPE_NONE on activation. This isn't exactly how the traditional airstuck worked but it is fun. Since it is done by changing MoveType, when you release the airstuck you keep your velocity at the time you held it. Wallstuck is same as airstuck but it only works on walls and while mid-air (and ofc when your MoveType is MOVETYPE_WALK ). Wallstuck is same as airstuck but you don't keep your velocity. This feature is THE airstuck that people wanted, not the +airstuck. Since all of these getting "stuck" are made possible by changing the MoveType, you are more accurate while being stuck than being actually mid-air. Hopefully changing the MoveType doesn't lead to problems I didn't know that could happen :) Let me know what you think, your feedback is important. (edited)

Update 0.11 Improved Edgesurf New Commands: !es or !edgesurf: opens dystopia edgesurf settings menu +edgesurflock is removed, replaced by +edgesurflocklegacy Now edgesurf-lock is integrated inside edgesurf, you can enable it with the !es menu. Explaination of !es settings: chat indicator: displays edgesurfing on chat with your prefix when you are edgesurfing, just like edgebug chat prints. edgesurf-lock: the optimized, improved version of the old +edgesurflock, intergrated inside +edgesurf edge magnet: wraps around edges, you can hold down edgesurf while this is enabled and stick to edge, or take turns with it sticking you to edges keep edgesurfing on release if edgesurfing: it keeps you at edgesurfing state even if you release +es, this way you can release your key after initiation accelerate: accelerates the player using a real wallstrafing logic, doesnt apply speed randomly, think of it as an autowallstrafe with the wall below you minimum lock speed: this feature is for edgesurf-lock and edge magnet. edge magnet and edgesurf-lock won't clip your velocity if the result is less than the value you set, you can set this value to 1 and it will prevent dead-stops. minimum lock degrees: just like the previously mentioned setting, edge magnet and edgesurf-lock won't clip your velocity if the wall's normal and your velocity have a smaller angle than this. recommended range 1-45 keep +edgesurf active after edgesurf disconnect: this feature allows the feature to be activated for x amount of seconds set after disconnecting with an edgesurf. this way if you disconnect from a surf for a split moment, it will keep +es on for x amount of seconds set. this feature is best paired with "keep edgesurfing on release if edgesurfing". virtual wall height of edgesurf-lock: recommended by raelc, this determines how long will the virtual wall you are colliding with will be. think of edgesurf-lock as colliding with a wall, this value determines the extention of that wall. !autowallstrafe (opens auto-wallstrafe menu) +aws, +autowallstrafe now pixelsurf can pixelsurf almost everything, try new spots with fixed +jetpack, you will find a lot more. if you don't like it, go to the !ps menu, change Pixel Processing settings. 7th option forward BSP processing catches real pixelsurfs 8th option backward BSP processing flips the process priority to hit pixelsurfs/pixelhops that forward BSP processing can't hit 9th option texture differences is the legacy dystopia pixelsurf detection auto-wallstrafe is added now and even if you don't use the standalone feature (+autowallstrafe/+aws), you can make it so it runs while you are pixelsurfing from ps menu: !ps. auto-wallstrafe works both in air and on ground, for it to work on ground you need to go past some threshold, the threshold where the perfect angle isn't in the same direction as the velocity. auto-wallstrafe doesn't apply velocity to client, actually calculates the perfect gain angle and then strafes to that direction. if you don't like the "flick back" when you strafe towards the back, use the second option in the !aws menu, if you don't like that auto-wallstrafe is working even when you don't send any keys, use the third option and lastly for always-on use the first option in the menu. pixelhop uses the same process information that the pixelsurf does. now you can uncap the jump speed from !ph menu. added chat prints for both pixelhop and pixelsurf, they use your prefix that you set using the command !prefix. added an always-on option that will remember your choice in the menus, so you don't have to put +command in the console every time. while using pixelsurf if you enable third option you will see chat prints will have process information, you can use that to distinguish between the surf types but be warned, since you will transition between different process modes on surfs it will spam in chat, because it prints again every time new information is caught. fixed some initialization bugs on both pixelsurf, edgesurf, pixelhop and jetpack. if you see any issues let me know in #issues this was my dream update since day1. finally here for us to enjoy :) hf!
